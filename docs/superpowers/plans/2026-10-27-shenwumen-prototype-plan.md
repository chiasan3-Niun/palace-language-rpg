# 神武門單關原型實作計畫

## 目標

在不使用後端的前提下，完成一個可在瀏覽器重玩的神武門單關原型，涵蓋對話、六書／字形判斷、提示、容止值／才情值、錯誤重試、失敗畫面與知識整理卡。

題目採「專案自編、教師可審查」來源策略。原型題目可以先使用待審查內容測試互動，但資料必須保留來源狀態，不得把未審查內容標成正式答案。

## 檔案配置

- `src/index.html`：瀏覽器入口與主要 UI 容器。
- `src/styles.css`：古風介面、響應式配置、可讀性與狀態樣式。
- `src/app.js`：遊戲狀態、流程轉換、答題與提示行為。
- `src/data/levels.js`：神武門關卡資料、對話、題目、回饋與學習卡。
- `src/ui/dialogue.js`：對話文字、角色立繪與選項的渲染。
- `src/ui/status.js`：容止值、才情值與提示狀態的渲染。
- `src/ui/feedback.js`：答題結果、重試、成功與失敗畫面的渲染。
- `public/images/...`：沿用既有神武門背景、角色、道具與 UI 素材，不重新生成圖片。

若專案現有程式結構與上述配置不同，先保留現有結構，將功能對應到現有責任相同的檔案，不為原型額外重構。

## 工作步驟

### 1. 建立最小入口與固定畫面區域

- 建立背景、狀態列、角色區、對話框、選項區、提示區與回饋區。
- 以 `BG_01_SHENWUMEN.png` 作為神武門場景。
- 使用既有 SVG UI 素材；文字放在 HTML/CSS 層，不烘進圖片。

驗證：用瀏覽器開啟入口時，背景與主要區域皆可顯示，且文字不直接落在難以閱讀的背景細節上。

### 2. 建立關卡資料與來源狀態

- 在 `levels.js` 建立 `level-01`。
- 加入任務目標、知識點、對話節點、選項、題目選項、答案欄位、判斷依據、答對／答錯回饋與學習卡。
- 將題目標記為待審查狀態，保留日後填入教材或教師審查資訊的欄位。

驗證：不修改核心 UI 程式，只改關卡資料即可替換題幹與回饋文字。

### 3. 實作對話流程

- 實作開場、宮門官盤問、玩家回應與進入題目的狀態轉換。
- 合宜回應不扣容止值；失禮或逃避回應扣容止值 10 點，但仍能進入題目。
- 讓同一關可由重新開始按鈕回到初始狀態。

驗證：可從開場走到題目，且選擇不同對話回應會產生不同狀態回饋。

### 4. 實作答題與即時回饋

- 顯示單題選擇題與送出按鈕。
- 答對增加才情值 10 點，顯示判斷依據並進入成功流程。
- 答錯扣容止值 15 點，顯示錯誤原因與重新判斷按鈕。
- 容止值歸零時進入「任務失敗，重新推理」畫面，不呈現暴力處罰。

驗證：至少通過答對、答錯後重試、容止值歸零三條流程。

### 5. 實作兩層提示

- 語意點醒不扣才情值，只顯示閱讀方向。
- 排除陷阱扣才情值 10 點，移除一個錯誤選項並顯示提示說明。
- 每一層提示每題最多使用一次；才情值不足時不能使用第二層。

驗證：提示的扣值、選項變化與使用次數正確，且使用提示後仍需玩家自行選答案。

### 6. 實作成功畫面與知識整理卡

- 顯示「神武門驗籍完成」與本關取得的知識整理卡。
- 卡片包含知識名稱、簡短判斷方法、題目中的判斷依據與待審查標記。
- 提供重新遊玩按鈕。

驗證：成功流程能看到學習卡，重新遊玩後數值和提示狀態回到初始值。

### 7. 進行結構與瀏覽器驗證

- 檢查 JavaScript 語法與資料結構。
- 以本機 HTTP 方式預覽，不以 `file://` 作為唯一測試方式。
- 以桌面與窄螢幕尺寸檢查題幹、選項、回饋和按鈕是否可讀。
- 使用一位不看程式碼的測試者完成一輪，詢問其答題理由。

驗證：測試者能說明答題依據，而不只是說「系統判定正確」。

## 完成條件

- 能在瀏覽器完成神武門一輪。
- 對話、題目、提示、狀態、回饋與學習卡均能運作。
- 答錯可重試，容止值歸零會進入安全的失敗畫面。
- 題目來源狀態清楚，未審查內容沒有被標成正式教材答案。
- 不需修改核心程式即可替換關卡文字資料。
- 完成結構驗證與基本實際操作驗證後，才能宣稱原型完成。

## 不在本次計畫內

- 其餘 11 關。
- 拖曳造字與複合型解謎。
- 後端、帳號、存檔、音效與多結局。
- 角色命名與影視角色版權的最終決定。
