# 專案規格

## 1. 產品定位

《紫禁深宮·語文策》是教育對話 RPG。遊戲中的語文知識不是獨立題庫，而是玩家在宮廷情境中用來理解文本、判斷意圖與完成論辯的工具。

## 2. 核心遊戲循環

```text
閱讀情境 → 選擇回應 → 使用語文知識判斷 → 得到即時回饋 → 改變角色狀態 → 推進劇情
```

每一關至少應包含：

- 一個明確的劇情任務。
- 一個主要語文知識點。
- 一次可理解的判斷或解謎。
- 正確與錯誤選擇的不同回饋。
- 一張可帶走的知識整理卡。

## 3. 第一版資料模型

```js
{
  id: "level-01",
  title: "神武門",
  objective: "完成秀女名冊驗籍",
  lesson: "漢字形體演變與六書",
  scene: "BG_01_SHENWUMEN",
  dialogue: [],
  questions: [],
  rewards: [],
  failure: { type: "retry" }
}
```

## 4. 角色狀態

| 狀態 | 初始值 | 作用 | 第一版規則 |
|---|---:|---|---|
| 容止值 | 100 | 代表目前的宮中處境 | 答錯或失禮時下降；歸零進入失敗結局 |
| 才情值 | 0 | 使用提示與特殊回應 | 答對時增加；提示消耗才情值 |
| 皇上猜忌值 | 0 | 控制後期壓力 | 第一關先保留欄位，不加入複雜分支 |

## 5. 教學鷹架

第一版只實作兩層，先確認學生真的會使用：

1. 語意點醒：不扣才情值，指出閱讀方向。
2. 排除陷阱：扣除少量才情值，移除一個錯誤選項。

第三層微課錦囊等教學內容穩定後再加入。

## 6. 技術邊界

原始設計提出單一檔案 HTML5／SPA、Tailwind CSS 與 Web Audio API。第一版先以可維護的多檔案結構製作，確認玩法後再視需要合併部署。

建議目錄：

```text
src/
  index.html
  styles.css
  app.js
  data/
    levels.js
  ui/
    dialogue.js
    status.js
    feedback.js
public/
  images/
  audio/
```

## 7. 尚未定案的內容

- 歷史人物與影視角色的使用範圍及命名方式。
- 教學題目的正確答案與教材來源。
- 「打倒皇上」結局的敘事尺度與適齡處理。
- 是否需要玩家存檔、帳號或後端。
- AI 生成圖片的實際授權與製作流程。
